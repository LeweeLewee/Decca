# Decca ADC PWM noise diagnostic report

## Result

The evidence best supports **A. PWM/MOSFET switching interference**, but only as
a modest contributor to raw ADC noise. Confidence is **moderate (70%)**.

Removing 1 kHz switching reduced raw standard deviation consistently across all
four pots by 6.8–10.3%, and reduced filtered standard deviation by 8.2–14.7%.
However, raw peak-to-peak range did not improve consistently, and the existing
filter/deadband stack eliminated all UI-trigger-sized filtered excursions in both
phases. The data therefore does not support a firmware filtering/UI defect as the
primary cause.

## Controlled conditions

- Phase A: duty **217/255** at **1 kHz PWM**
- Phase B: duty **255/255**, with LEDC detached and GPIO25 held continuously
  `HIGH` (constant GPIO output, not nominal 100% PWM)
- Phase A timing: 6,000 samples, 599,900 ms from first to last sample, every gap
  exactly 100 ms
- Stabilisation: 7.5 seconds after setting duty 255 and reaching full brightness
- Phase B timing: 6,000 samples, 599,900 ms from first to last sample, every gap
  exactly 100 ms
- Pots: no test procedure touched or requested movement of any potentiometer
- Pre-test restoration: device reported `restored_pwm=217` immediately after
  Phase B, before buffered Phase B data transmission
- Normal firmware restoration: authenticated OTA succeeded and mDNS/OTA returned

The measurement rows were buffered on-device and transmitted outside the phase
measurement windows. This prevents laptop scheduling or TCP backpressure from
altering the 100 ms sampling cadence. Phase A data transfer occurred before the
7.5-second transition; Phase B restoration occurred before its data transfer.

## Raw-versus-filtered comparison

Filtering reduced standard deviation by 62.3–64.6% in Phase A and 62.8–67.2%
in Phase B. It reduced peak-to-peak range by 37.5–54.8% in Phase A and
38.5–54.8% in Phase B. Most importantly, filtered UI-sized excursion counts were
zero for every pot in both phases, compared with 107 total raw events in Phase A
and 79 in Phase B.

The no-switching phase reduced standard deviation consistently:

| Pot | Raw std-dev change A → B | Filtered std-dev change A → B |
|---|---:|---:|
| Volume | -6.8% | -8.2% |
| Bass | -6.9% | -14.7% |
| Treble | -10.3% | -12.6% |
| Balance | -8.4% | -12.9% |

Mean shifts were small and positive (+0.31 to +0.48 ADC count) in Phase B. Raw
peak-to-peak changes were mixed (31→31, 32→33, 27→26, 24→28), so the experiment
does not show PWM switching as the only noise source.

## Diagnosis: evidence versus inference

Direct evidence:

- Constant-high/no-LEDC operation modestly lowered standard deviation on every
  ADC channel.
- The filtered/UI path produced zero trigger-sized excursions in both phases.
- Small common positive mean shifts occurred when the lamps changed from 85% PWM
  to continuously on.
- There was no startup-only sampling window; both phases were fully stabilised and
  exactly ten minutes long.

Inference:

- PWM/MOSFET edge coupling is a real but secondary component of the raw noise.
- The small common mean shift is compatible with a minor shared supply/ground
  effect caused by the higher continuous lamp current, but it is too small and the
  noise reduction is too switching-correlated for shared supply/ground noise to
  be the primary explanation.
- ADC startup stabilisation is not supported by this test.
- The current smoothing and UI thresholds are effective under these stationary
  conditions; a persistent real-world UI issue would more likely require a loose
  wiper/ground connection, a different operating condition, or a transient not
  present here.

## Recommendation

No brightness or production-filter change is justified by this result. Keep the
normal 217/255 at 1 kHz and the existing EMA/deadband/UI thresholds.

For additional raw-noise margin, improve the analogue return path first: star-route
pot grounds away from lamp/MOSFET current, shorten analogue leads, add local 3.3 V
decoupling, and consider a small per-channel RC filter close to the ESP32 ADC input
(component values should be validated against pot impedance and response time).
If edge coupling remains measurable, add modest slew/edge control at the DFR0457
input and keep GPIO25 wiring separated from ADC leads. Re-run this same diagnostic
after any hardware change.
